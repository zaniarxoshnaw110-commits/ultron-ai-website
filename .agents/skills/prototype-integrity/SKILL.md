# Prototype Integrity
- Label simulated output where users encounter it, not only in a distant README.
- Never describe keyword matching as model reasoning, procedural art as a neural network, or static examples as live AI.
- Don't imply data was sent, saved, analyzed remotely, or acted upon when no such operation occurred.
- Make local-only processing and data retention behavior explicit and accurate.
- Prefer a useful, honest simulation over fake loading, fake progress, fabricated metrics, or invented testimonials.
- Ensure call-to-action labels match their actual destination and outcome.
